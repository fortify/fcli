Name

fcli-util-rpc-server-start - (PREVIEW) Start fcli JSON-RPC server for IDE plugin integration

{% raw %}

Synopsis

fcli util rpc-server start [--async-bg-threads=<bgThreads>] [--import=<importFiles>[,<importFiles>…​]]…​ [[-h] [--env-prefix=<prefix>] [--log-file=<logFile>] [--log-level=<logLevel>] [--log-mask=<level>] [--debug]]

Description

The fcli JSON-RPC server provides a simple JSON-RPC 2.0 interface for IDE plugins and other tools to interact with Fortify products through fcli. Unlike the MCP server which is designed for LLM integration, the RPC server exposes a smaller set of general-purpose methods suitable for programmatic access from IDE plugins.

The server reads JSON-RPC 2.0 requests from stdin and writes responses to stdout, one JSON object per line.

AVAILABLE RPC METHODS

  • FCLI METHODS (fcli.*):

    fcli.execute:
  Execute an fcli command asynchronously
  Parameters:
    - command (string, required)
      The fcli command to execute (e.g., "ssc appversion list")
    - collectRecords (boolean, optional)
      By default, stdout is suppressed and records are collected
      if supported by the fcli command, unless this parameter is
      set to false.
    - cache (object, optional)
      Enable record caching for retrieval via job.getPage.
      Omitted: no caching.
      {ttl: "<period>"}: cache with specified TTL (e.g., "30s",
      "5m", "1h", "1d"). TTL is required.
      Cached records are automatically evicted after TTL.
      Use job.remove to clear the cache before TTL expires.
    - push (boolean, optional, default: true)
      Enable push notifications (job.started, job.records,
      job.progress, job.complete). Set to false to disable all
      push notifications and rely on job.getStatus/job.getPage
      for polling.
  Response:
    jobId, status="started", jobType ("records" or "stdout"),
    cached (boolean)
    fcli.listCommands:
  List available fcli commands with optional SpEL query filtering
  Parameters:
    - query (string, optional)
      SpEL expression to filter commands (e.g., '!hidden && runnable',
      'module=="ssc"'). See 'fcli util all-commands list -o json' for
      available properties.
  Response:
    commands (array of command descriptors), count
    fcli.getCommandDetails:
  Get detailed spec and argument information for a specific fcli command
  Parameters:
    - command (string, required)
      The fcli command to describe (e.g., "ssc appversion list")
  Response:
    command, commandSpec, commandArgs
    fcli.buildInfo:
  Get fcli build information
  Parameters: none
  Response:
    projectName, version, buildDate, actionSchemaVersion, actionSchemaUrl, docBaseUrl, sourceCodeBaseUrl

  • FUNCTION METHODS (fn.*) — only available when --import is used:

    fn.call:
  Call an imported action function asynchronously
  Parameters:
    - name (string, required)
      Function name (see fn.list)
    - args (object, optional)
      Function arguments as key/value pairs
    - cache (object, optional)
      Enable record caching for retrieval via job.getPage.
      Same options as fcli.execute cache parameter.
    - push (boolean, optional, default: true)
      Enable push notifications. Same as fcli.execute push
      parameter.
  Response:
    jobId, status="started", jobType="records",
    cached (boolean)
    fn.list:
  List available imported action functions
  Parameters: none
  Response:
    functions (array of {name, description, streaming}), count

  • JOB METHODS (job.*):

    job.getPage:
  Retrieve a page of records from a running or completed job.
  Only available for jobs started with cache enabled.
  Returns status="not_found" if caching was not enabled or
  if the cache has been evicted (TTL expired).
  Parameters:
    - jobId (string, required)
      Job ID from fcli.execute or fn.call
    - offset (integer, optional)
      Start offset (default: 0)
    - limit (integer, optional)
      Max records per page (default: 100)
  Response:
    status ("complete", "loading", "error", or "not_found"), jobId, records,
    pagination ({offset, limit, loadedCount, hasMore, complete}),
    exitCode (if complete), stderr (if any), stdout (for stdout-mode jobs, if complete)
    job.cancel:
  Cancel a running job
  Parameters:
    - jobId (string, required)
      Job ID to cancel
  Response: success, jobId, message
    job.getStatus:
  Get the status of a single job
  Parameters:
    - jobId (string, required)
      Job ID to query
  Response:
    jobId, status ("running", "complete", "error", or "not_found"),
    description, completed, exitCode, cached, createdMillis
    job.remove:
  Remove a completed job from tracking and clear its record cache
  Parameters:
    - jobId (string, required)
      Job ID to remove (must be completed; cancel running jobs first)
  Response: success, jobId, message
    job.list:
  List all tracked jobs
  Parameters: none
  Response: jobs (array of {jobId, description, completed, exitCode, createdMillis}), totalJobs

  • RPC METHODS (rpc.*):

    rpc.listMethods:
  List all available RPC methods with descriptions
  Parameters: none
  Response: methods (array of {name, description}), count

PUSH NOTIFICATIONS (server-to-client, no id field):

The fcli.execute and fn.call methods are asynchronous and will return immediately with a jobId. By default (push: true), the following notifications are actively pushed to the client during job execution. Set push: false to disable all push notifications and use job.getStatus / job.getPage for polling instead.

  • job.started: Sent when a job begins execution (params: jobId, description)

  • job.records: Batch of records produced by a running job (params: jobId, records, count)

  • job.progress: Progress message from a running job (params: jobId, message)

  • job.complete: Sent when a job finishes (params: jobId, exitCode, stderr?, stdout?)

TYPICAL WORKFLOW:

  1. Establish fcli sessions using standard fcli session login commands via fcli.execute

  2. Execute commands and functions via fcli.execute and fn.call (always async, returns jobId)

  3. Listen for push notifications (job.started, job.records, job.complete)

EXAMPLE JSON-RPC REQUESTS:

{"jsonrpc":"2.0","method":"fcli.execute","params":{"command":"ssc appversion list","collectRecords":true},"id":1} {"jsonrpc":"2.0","method":"job.getPage","params":{"jobId":"<jobId from above>","offset":0,"limit":100},"id":2} {"jsonrpc":"2.0","method":"job.list","id":3} {"jsonrpc":"2.0","method":"fcli.getCommandDetails","params":{"command":"ssc appversion list"},"id":4} {"jsonrpc":"2.0","method":"rpc.listMethods","id":5}

Options

--async-bg-threads=<bgThreads>

Number of background threads for running async jobs. Increase if IDE clients submit many concurrent async commands. Default: 4.

--import=<importFiles>[,<importFiles>…​]

Action YAML files to import. Exported functions are accessible via the fn.call and fn.list RPC methods.

Generic fcli options (also see documentation link below)

--debug

Enable collection of debug logs.

--env-prefix=<prefix>

Prefix for resolving default option values. Default value: FCLI_DEFAULT.

-h, --help

Use 'fcli [command] -h' to display help for fcli (sub-)commands.

--log-file=<logFile>

Write log output to file. Default: ./fcli.log if logging is enabled.

--log-level=<logLevel>

Set logging level: TRACE, DEBUG, INFO, WARN, ERROR, NONE.

--log-mask=<level>

Log mask level: high, medium, low, none. Default: medium. Masking is done on a best-effort basis; no guarantee that all sensitive data will be masked.
